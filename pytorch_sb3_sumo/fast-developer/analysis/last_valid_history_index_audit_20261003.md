# Last-valid history index audit (2026-10-03)

## Finding

The environment keeps the current raw state at the end of the neighbor history window. The D1 encoder derives neighbor validity from the first state coordinate and then uses `valid.sum() - 1` as though valid rows always form a prefix. Under the SMARTS left-padding contract, a short neighbor history is a suffix of valid rows (and can also have right padding during episode startup), so this count-based gather may select padding or an older row. This is a model-side indexing defect; it does not mean the environment overwrote the current raw observation.

The production mask is exactly `return values[..., 0] != 0` in [`features.py`](<D:/Program Files (x86)/paper/Scene-Rep-Transformer-main1/Scene-Rep-Transformer-main/pytorch_sb3_sumo/algos/sb3_torch/features.py:44>). It checks only x, not all state fields and not whether the full row is zero. The D1 encoder imports this same helper (`incremental_topo_encoder.py:38`) and computes it before rotation (`incremental_topo_encoder.py:557-558`). Thus an otherwise nonzero valid state with x=0 is classified as invalid; a truly stationary zero state at the origin is indistinguishable from padding under this contract.

## Environment layout and cadence

The D1 observation is `trajectory[actor, time, feature]` with shape `[6, 10, 5]`: ego at actor 0, up to five nearest neighbors at actors 1–5, and ten history rows (`sumo_env.py:294,304`; construction at `1966-2008`). The environment records histories for all active in-network actors, not only the five neighbors later chosen for the observation (`sumo_env.py:1757-1801`; nearest-neighbor selection is separate at `1866-1910`). Consequently, merely entering the nearest-five set does not imply short history. Short histories mainly arise when an actor is first seen/spawned; SMARTS gaps after a previously seen actor reappears are filled by linear interpolation (`sumo_env.py:1812-1830`). The exact exposure frequency in the trained/evaluated trajectories remains unknown and needs an observation-level count.

`_history_array` places a SMARTS neighbor's `m` available rows at the end of the episode history available so far (`sumo_env.py:1913-1942`): if `p=min(_history_timestep,H)`, valid rows occupy `[p-m, p-1]`, with `H-p` right-padding rows during startup. The actual current index is therefore `p-1`, consistent with `_current_observation_row` in the conflict-timing wrapper (`conflict_timing_observation.py:162-174`). SUMO uses a 0.1-second step (`paper_env.py:229-240`), histories append after every raw simulation step, and `action_repeat=3` (`sumo_env.py:250,284,600-605`): history spacing is 0.1 s and policy decisions are 0.3 s apart.

## Affected model paths

`IncrementalTopoEncoder` first masks and encodes each trajectory row, then calls inherited `_last_valid` to form `current_state` (`incremental_topo_encoder.py:557-564`; helper at `topo_temporal_features.py:469-474`, inherited by V2). The helper gathers index `valid.sum(-1)-1`. With route enabled, that gathered token becomes the per-actor route-attention query (`incremental_topo_encoder.py:583` onward). If it selects padding, the selected `state_token` is zero because the encoder already multiplies it by the validity mask; if it selects an older valid row, that row's position and speed are stale. This route path is present in ST-RT, longres, and route-enabled D1 variants.

Independently, the D1 path forms `graph_sequence` and sends it to `TemporalInteractionEncoder` (`incremental_topo_encoder.py:774-786`). The temporal encoder also uses `flat_valid.sum()-1` at `topo_temporal_features.py:293` to select one query row after temporal self-attention. Its self-attention is noncausal: it passes a key-padding mask but no causal attention mask (`topo_temporal_features.py:284-300`). Padded query rows are zeroed after self-attention (`291-292`), but the subsequent pooling attention can still produce a nonzero result from valid keys (`296-303`). An older valid query has already attended to all valid time keys, including later/current rows. The issue is therefore a wrong query position/lag signal, not a claim that the pooled feature must be zero or that the current frame is completely absent. The resulting actor features feed social attention as keys/values (`incremental_topo_encoder.py:786,851-852`) and then the selected readout/slot head.

The finding applies to methods that actually use `IncrementalTopoEncoder`: `sac_mlp_d1_st` (without route), `sac_mlp_d1_st_rt`, `sac_mlp_d1_st_rt_longres_v1`, and D1 topology/slot variants, including the D1 `sac_mlp_d1_full` configuration (`train_intersection_yield_v2_d1.py:728-839,1116-1117`). In ST without route, the route-query gather is computed but is not used; the temporal query gather still applies. Longres disables the separate route-conflict-timing encoder but shares the same D1 history encoder. Its conflict-timing wrapper independently selects the current raw row by global timestep and is not the source of this count-minus-one defect.

The pure `sac_mlp` baseline uses `SimpleMlpLstmExtractor` with `backbone="mlp"` (`train_intersection_yield_v2.py:799-827`): its default temporal operation is a masked mean (`simple_encoder.py:115-130`), not a neighbor last-row gather. The optional LSTM backbone does use count-minus-one, but it is not the configured baseline here. MST+SLT uses `HierarchicalSceneExtractor` (`configs/sb3_configs.py:89-96`), whose temporal actor encoder max-pools across time (`features.py:193-221`), so it does not share the D1 neighbor query-index defect. Its ego-frame helper also uses count-minus-one, but ego histories are prefix-valid in this contract (`features.py:346-350`). A separate existing MST+SLT behavior checks neighbor validity only at time index 0 (`features.py:459-463`); under left-padding this can exclude a short-history neighbor from actor interaction. The source comment describes this as released behavior. Whether the intended input contract required a complete neighbor history is unknown, so this audit records it as a protocol/behavior boundary rather than asserting a separate defect.

## Pure tensor reproduction

The reproducible script is [`last_valid_history_index_repro_20261003.py`](<D:/Program Files (x86)/paper/Scene-Rep-Transformer-main1/Scene-Rep-Transformer-main/pytorch_sb3_sumo/fast-developer/analysis/last_valid_history_index_repro_20261003.py>). It constructs only synthetic PyTorch tensors and compares the production count-minus-one rule with the greatest valid index and the environment's global current index. It does not import or instantiate the simulator or a policy.

For a mature H=10 window with five left-padded neighbor rows, it reports mask `0000011111`, count-minus-one index 4 (invalid padding; x=0, vx=0), and max-valid index 9. The 0.5-second index difference is a distance to padding, not a 0.5-second-old real observation. With six valid suffix rows and four left-padding rows, count-minus-one selects real row 5 (x=105, vx=15) while the current row is 9 (x=109, vx=19), a true 0.4-second stale selection. During startup with global history timestep 6 and two valid rows at indices 4–5, count-minus-one selects index 1 (left padding), while the current/max-valid row is 5. A right-padded prefix and a fully valid history select the true last row. A mask with holes `[0,3,4,8]` demonstrates that count-minus-one also fails for non-prefix masks. The all-zero stationary-origin and valid-x-zero cases expose the first-coordinate sentinel limitation.

## Evidence limits and run status

This is a static implementation finding plus a synthetic index reproduction. It does not establish how often the affected histories occur in traffic, nor how much they change policy actions or performance. Two bounded live-observation snapshots were also checked: retry01 ST-RT at raw step 10002/decision 22 and the isolated longres root at raw step 10000/decision 33. Both observations had shape `[6,10,5]`; under the production x-nonzero proxy all six actor slots had ten valid rows, so count-minus-one and max-valid both selected index 9. These two threshold samples do not estimate short-history exposure. They contain no actor IDs, actor first-seen times, explicit presence mask, or history-reset metadata, so they cannot reconstruct actor lifetimes. The current 12-window diagnostic set is outcome-stratified (8 collision, 4 success) and must not be treated as a population prevalence or success-rate estimate; any per-window audit establishes exposure only in those selected cases.

The two `sortlr_1003_retry01` runs were already trained with this implementation. The prior archive-manifest comparison recorded matching training/environment source hashes for the two runs; the history-index code had not been changed. Their results therefore remain evidence for the old encoder and must not be described as a repaired-index comparison. No production source was changed during this audit, and no SUMO simulation or training was run.
