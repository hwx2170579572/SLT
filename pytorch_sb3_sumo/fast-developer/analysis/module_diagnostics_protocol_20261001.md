# Module diagnostics protocol (2026-10-01)

This records what the normal training/evaluation path samples and what each signal can support. Diagnostics use tensors from the current forward/backward only; they add no model forward, backward, optimizer step, action, or random draw.

| Evidence | Sampling point and denominator | What it can indicate | Main limit |
|---|---|---|---|
| Encoder activation snapshot | Each configured callsite has its own forward counter; sample first, then every configured interval (256 by default). The critic TD-current forward is forced on update 1 and every 1000 updates. Metrics are detached and copied in one scalar batch. | Whether spatial messages, temporal processing, social attention, route attention, topology attention, or slot projections are active at sampled inputs. | A forward magnitude/attention allocation is not causal credit or proof of policy reliance. A cached sample is tagged with its actual callsite/update and age; it is never relabeled as a newer update. |
| ST/spatial-temporal | Spatial message delta RMS/relative RMS averages valid actor-time frames; history counts use valid actor histories. Temporal delta compares the actor representation with the last valid post-spatial frame, averaged over valid actors. | Small spatial delta or temporal delta, and the single-valid-frame fraction, can flag a weak branch or limited usable history. | These are magnitude comparisons from one forward, not ablations; residual scales/normalization affect magnitude. |
| Social attention | Entropy/effective actor count, ego self-mass, non-ego mass, and valid actor count are aggregated over batch queries. | Whether social attention distributes weight beyond ego or concentrates on a few valid actors. | Attention weights do not establish that downstream behavior depends on those actors. |
| RT/map-route | Valid route-path count and empty fraction; route-path attention entropy/effective paths are computed for the ego route slot only. | Whether route candidates exist and how attention is distributed among valid ego paths. | Does not measure route-token counterfactual value; route encoding and downstream fusion remain mixed. |
| Topology actor-intent residual (incremental D1) | Only on an already sampled Topo forward, compare the actual valid-frame `LayerNorm(intent + alpha * topology_context)` with detached `LayerNorm(intent)` using the same LayerNorm parameters. Report post-LN delta RMS, baseline RMS, relative RMS and valid actor-history-frame count/flag. This includes the LN effect and is distinct from the raw scalar `topology_residual_scale`. | Whether the Topo actor-intent branch measurably changes the representation entering spatial vehicle messages after normalization. | It is an observed representation difference, not an ablation or causal contribution to action/value; an extra detached LayerNorm is evaluated only at sampled points. The off-branch LayerNorm is otherwise the ordinary no-Topo path. |
| Topology relation support baseline (incremental D1) | At the same sampled forward, use the exact post-compatibility/top-k/fallback `topology_key_mask` that lane attention received. For each valid actor/history query define a uniform distribution on its selected candidate lanes; compare same-lane, conflict, merge and combined conflict-or-merge pair scores under the identical valid actor-pair/support mask. Record candidate-query count, mean candidate count, supported actor-pair count, validity, actual matched-support mean, uniform-support mean and actual-minus-uniform difference. | Whether the attention distributions emphasize lane relations more/less than a simple uniform distribution over the same available candidate sets. | Uniform lift is a descriptive selectivity baseline, not a learned-relation counterfactual or causal effect. It is not the global graph edge density; invalid/diagonal actor pairs and queries with no selected candidates are excluded from both means. The model's actual conflict/merge edge feature remains a single combined channel. |
| Topology/route-aware goal | Existing topology attention entropy, effective lane count, route-compatible mass and valid-query/fallback denominators; route-aware mode adds legal/known/unknown candidate counts, query-intersection, expansion/bypass/fallback rates, legal attention mass, and goal-delta norms. `goal_topology_delta_rms` is already the actual post-LN `route_context_final - route_base`; route-aware mode additionally has legal-active norm/count. | Whether the current topology queries attend to compatible nodes, or route constraints expand/bypass the geometric candidate set; the actual goal-readout delta is kept separate from actor-intent delta above. | Compatibility in the base encoder is its direction/geometry mask, not full map route-continuation legality. Route-aware labels are known only where the static graph mapping supports them; unknown is not treated as illegal. Do not duplicate the existing post-LN goal delta field. |
| Slot activations/readout | For batch size >=2, per-slot RMS, per-dimension batch std, within-sample std, energy share and valid energy correlations; batch-one variance/correlation flags are invalid. Eval records the exact additive contribution of each 32/64/32 input slice to the existing first actor Linear preactivation, plus reconstruction error. | Can expose dead/low-variation slots or an actor readout that gives a slice small preactivation contribution on observed examples. | Slot energy is not causal attribution; components can cancel. The readout decomposition is only the first actor Linear, before its downstream nonlinear layers, and is collected in existing evaluation predictions. |
| Parameter gradients and updates | At critic TD update 1 and every 1000 updates, disjoint encoder leaf groups plus overlapping `encoder_all` summary are inspected after `critic_loss.backward()` and before clipping. A detached pre-step snapshot of critic-optimizer-owned parameters is compared immediately after its step. | Distinguishes missing vs allocated-zero vs nonzero gradients, optimizer ownership, and whether owned parameters changed. | These gradients are critic TD evidence, not actor-gradient evidence: the shared actor extractor is detached and excluded from the actor optimizer. Representation-objective optimizer changes, if enabled, are separate from the `critic_td_parameter_update` event. Do not sum overlapping summary/leaf norms. |

Training event callsites distinguish rollout policy, representation-objective online, current critic TD, current actor policy, actor next-action (no-grad), and critic actor-value forwards. Eval samples the existing deterministic `predict` call and logs episode index/seed, decision/raw-step position, action, and sample index. `train_replay` is a phase/configuration label; the online extractor can also be shared by rollout actor forwards, so use the explicit callsite metadata to identify the actual source.

Enabled training gradient/update sampling performs a bounded scalar device-to-host transfer at the sampled update. Evaluation slot-readout hooks use the existing actor forward and do not alter its output. Diagnostics-on/off output, gradients, and RNG are covered by the targeted encoder test; tests do not launch SUMO or training.

Coverage boundary: the new actor-intent post-LN delta and matched-support relation-uniform metrics are implemented on `IncrementalTopoEncoder`'s incremental forward path, including the current route-aware and incremental-slot methods. The legacy all-on `use_route && use_topology && use_slots && !use_incremental_slots` delegate to `TopoTemporalGraphExtractorV2.forward_tokens` bypasses these two new metrics; that delegated full path is not in the current run queue and was not instrumented here. Existing goal post-LN delta metrics are separate and remain available where already implemented.

## 2026-10-02 bounded policy shadow probes

The D1 normal-flow extension is a same-observation deterministic policy probe, not another environment rollout. The training callback samples the action-input observation at raw-step thresholds after `learning_starts` (default interval 5,000 raw steps and at most 20 unique samples per 100k run). The evaluation predictor keeps at most three predeclared samples per episode: first valid multi-car input, first valid route-context input, and last existing preterminal prediction; duplicates are merged by decision index. A missing trigger is recorded as a skip/coverage reason by the runner. Probe predictions never execute an action or add a SUMO step, replay transition, or evaluation episode.

The active single-branch probes are `st_spatial_off`, `st_temporal_current_only`, `st_social_ego_only`, `rt_intent_injection_off`, `rt_route_readout_zero`, `topology_actor_intent_off`, `topology_relations_off`, `topology_goal_off`, `route_reachability_off`, and one-at-a-time `slot_{ego,social,route}_zero`. Applicability is computed from the actual encoder flags. Inactive branches are emitted with `applicable=false`, `valid=false`, and a reason, rather than a numeric zero. These probes are supported on `IncrementalTopoEncoder`'s incremental path; the legacy all-on parent-delegated forward is outside this run's probe support.

Each row is written independently to `diagnostics/{train|eval}/policy_shadow_probes.jsonl`, with a companion summary. It joins the selected sample ID to method/configuration, episode/seed, pre-observation raw and decision indices, update index, trigger, outcome, actual action and its source. A baseline and each applicable single intervention record pre-tanh actor mean, `tanh(mean)` normalized action, the policy-returned model action, pure SUMO action decoding, absolute/L2 action deltas before and after tanh, tanh saturation margin, distance to the lane-command thresholds, 128-D feature snapshot and any structured slot vectors. This makes saturation and discrete lane-command flips visible; it does not equate a small delta with a useless module.

During a probe the helper uses inference-only `model.predict` on the same observation and a temporary encoder context; it does not mutate encoder switches. It restores module train/eval flags, Python/NumPy/PyTorch CPU and initialized CUDA RNG states, module buffers and parameter gradients, encoder diagnostic counters/cache, and the temporary context/capture. The D1 caller separately snapshots/restores the pre-existing evaluation slot-readout hook scratch dictionaries. No parameter or optimizer update is performed. Probe variants start from the restored random state and use deterministic actions; forward hooks only capture values already produced by that forward.

Interpretation has three evidence levels. Existing activation/attention and gradient/update records show that a branch participated or received optimization signal. A valid same-state probe delta shows local functional sensitivity of the deterministic policy to that specific intervention. Neither level establishes that the branch improves task performance: slot zeroing and route/message bypasses may create internal states outside the trained distribution, and small action deltas can reflect redundancy, tanh saturation, or a weakly activated input. Performance attribution still requires the separately trained, paired evaluation comparison. Samples are trigger-selected and state distributions can differ by method, so report valid counts and context/outcome strata rather than treating probe rows as independent episodes or an unbiased population average.

## 2026-10-02 optional critical evaluation sampling

The D1 flag `--policy-shadow-critical-eval-sample` is default-off. It requires behavior diagnostics and policy shadow probes; function option `policy_shadow_critical_eval_sample=True`. With the default `policy_shadow_eval_max_per_episode=3`, the selector retains at most three unique decision states per episode: initial valid multi-car (falling back to route context), first qualifying critical state, and last existing preterminal prediction. This cap-3 behavior is retained for compatibility.

With the same flag and `--policy-shadow-eval-max-per-episode 4`, cap 4 reserves up to four unique states: initial valid multi-car (falling back to route context), first route-critical event, first TTC-critical event, and last preterminal prediction. If triggers refer to the same decision, their labels merge and consume one unique state; the merged row also retains critical-event context and action-window timing. Missing event types remain absent and are reported as not observed; no placeholder state is substituted. Cap 3 and cap 4 have distinct selector modes recorded per episode. Both caps are upper bounds, not guarantees of that many samples. Trigger labels/counts are not unique-state counts.

Critical events are read from existing environment/recorder telemetry. `known_unreachable_target_lane_requested` uses the decision-boundary route fields (`current_lane_can_reach_next_edge`, `expected_target_lane_can_reach_next_edge`, and nonzero `lane_command_requested`); the route fact is captured after the lane-change request API and before action-repeat simulation. `route_eligible_to_ineligible_post_transition` compares the previous known-true route status with the current known-false status, observed after the transition. `action_window_ttc_le_3s` requires a finite `min_cv_obb_ttc_s` in [0, 3] from the just-completed action-repeat window. For both event types, the selected policy input is the existing deterministic `predict` observation before the action whose completed window produced the event; the event/context fields are attached after that action. Thus the policy input is pre-action, while route-transition/TTC evidence may be post-action-window. Fields distinguish `source_action_pre_obs_raw_global_step` from episode-local `source_action_pre_obs_raw_episode_step`, and record `context_window_start_raw_{global,episode}_step` and `context_window_end_raw_{global,episode}_step`. The 3-second TTC value is a sampling trigger only, not a safety threshold. Missing or unknown route/TTC values remain null/NA and do not count as safe or as an event.

The episode coverage record distinguishes selected, observed-but-not-selected due to budget, not observed, and disabled triggers, and includes critical-event counts plus selector error count/details. Under cap 3, route and TTC share the first-critical slot, so the first event can exclude the other from the sampled states. Cap 4 removes that direct budget competition but remains first-event-per-type sampling: it can still miss later events, and a selected route/TTC state is not a representative sample of every risk window. Shadow probes add bounded model forward calls for selected states, but do not add a SUMO step, executed action, replay transition, or evaluation episode. Training sampling remains the existing periodic 5,000-raw-step schedule after `learning_starts` (at most 20 states); the split route/TTC cap applies only to evaluation.
