当前 108 项正式系统性实验矩阵的回合上限采用**作者发布源码口径**，不是论文表格口径。矩阵中的 `paper` profile 只表示训练预算为 100,000 raw SUMO steps、每模型测试 50 回合；环境上限由另一个独立字段 `episode_limit_profile="source"` 控制。

- 108/108 均使用 `traffic_protocol="frozen_80_20"`；
- 108/108 均使用 `traffic_partition="evaluation"`；
- 108/108 均使用 `episode_limit_profile="source"`；
- 每份评估均恰好包含 50 条 episode 记录；
- 每份评估的 seed 序列与声明一致；
- 所有 episode 的 raw steps 均未超过对应源码上限；
- 18 个“场景 × 训练 seed”配对组中，六种方法的 evaluation seed 和交通 XML 顺序完全一致。

### 1.1 指标口径

- **Success / Collision / Off-route：** 每个训练模型 50 个测试回合中的事件比例，再对 3 个训练 seed 求均值。
- **Return：** 使用逐 raw-step 的未折扣任务奖励累计值；到达为 `+1`、碰撞为 `-1`、其他 raw step 为 `0`。
- **Completion time：** 只对成功回合统计，按 `raw_steps × 0.1 s` 计算；表中为三个 seed 的成功回合均值再平均。它不是全部回合的 `mean_raw_steps`。
- **Train ms/update：** `performance_profile.json` 中端到端 learner update wall time 的三种子均值，只作为观察性效率指标。PPO 的 rollout、epoch 和 update 定义与 off-policy 方法不同，因此 PPO 与 SAC 家族的该列不能解释为完全同构的单次优化成本。
- **Off-route：** 全部 5,400 个正式测试回合中该指标均为 0，因而在本矩阵中没有区分力。

## 2. 方法论：TemporalGraph 与 Full+BalancedSlots

本节中的 **Full** 均指正式矩阵里的 **Full+BalancedSlots**（实现名 `topo_scene_balanced`）。TemporalGraph 与 Full 使用相同的 SAC、动作空间、奖励、训练 raw-step 预算、4-step replay、Graph-SLT 和 128 维结构化潜变量；主要差异位于场景编码器。

### 2.1 两种方法共享的输入与训练骨架

#### 2.1.1 场景输入

每个时刻的输入包含：

- 6 个 actor 槽位：ego 加最近 5 个交通参与者；
- 每个 actor 10 个历史 raw steps；
- 轨迹特征 `[x, y, heading, vx, vy]`；
- 每个 actor 的候选路线多段线：SMARTS 来源场景为两条，CARLA 重建场景为三条，每条保留 10 个点。

编码前将轨迹和路线转换到当前 ego 坐标系；训练时除 Double Merging 外保留源码随机旋转增强，evaluation 时关闭增强。

#### 2.1.2 状态—路线意图融合

状态 MLP 将每个 actor、每个历史帧编码为 128 维 token。候选路线由 polyline encoder 编码，actor 当前状态作为 query 对其候选路线做 masked cross-attention，得到 actor-specific route context。该 context 加入每个历史帧状态 token，形成带路线意图的车辆 token。

#### 2.1.3 逐帧车辆图先于时序汇聚

两种方法都避免先把整段历史压成单个 actor 表征。它们先在每一个历史帧上建立 6 车交互图，再进行时序编码。车辆边特征为：

```text
[Δx, Δy, Δvx, Δvy, cos(Δheading), normalized TTC, same-lane, conflict]
```

边权还包含基于车辆距离的高斯衰减：

\[
w_{ij}=\exp\left(-\frac{\|p_i-p_j\|^2}{2\sigma_v^2}\right).
\]

两个 residual vehicle-graph layers 对邻车消息加权聚合。之后，每个 actor 的 10 帧交互特征进入带 lag embedding 的 temporal self-attention，并以最后有效帧作为 query 对历史序列注意力池化。这样得到的 actor 表征同时包含“当时的空间交互”和“交互随时间的演化”。

#### 2.1.4 三槽结构化潜变量

时序编码后，ego token 对所有 actor 做 social attention，并分别投影为：

- `z_ego ∈ R^32`：ego 自身运动和局部状态；
- `z_social ∈ R^64`：邻车交互和社会上下文；
- `z_route ∈ R^32`：目标路线/道路上下文。

三者拼接为 128 维特征供 SAC actor 与 twin critics 使用。

#### 2.1.5 Structured Graph-SLT

两种方法都使用动作条件的一步结构化未来表征目标。动作先编码为 64 维，随后与完整潜变量拼接；每个语义槽使用独立 residual dynamics head：

\[
\hat z_k^{t+1}=z_k^t+f_k([z^t,\phi(a_t)]),
\quad k\in\{ego,social,route\}.
\]

每个槽通过独立 projector，与下一时刻的 stop-gradient target slot 计算负余弦目标：

\[
\mathcal L_k=1-\cos\bigl(P_k(\hat z_k^{t+1}),\operatorname{sg}(P_k(z_k^{t+1}))\bigr),
\]

最终 Graph-SLT 损失为三个槽损失的等权平均。该辅助目标与 SAC 更新并行训练编码器，目标是让 ego、社会交互和路线信息分别具有动作条件的可预测动态结构。

### 2.2 TemporalGraph

TemporalGraph 的配置为：

```text
use_topology = False
normalize_slots = False
```

其核心方法论是**先进行逐帧车辆交互，再进行时间建模**，但不引入静态全局车道拓扑。

完整信息流为：

```text
轨迹/候选路线
  → ego坐标对齐与有效性 mask
  → 状态 token + actor-specific route context
  → 每个历史帧的车辆交互图
  → 每个 actor 的 temporal self-attention 与历史池化
  → ego/social/route 三槽潜变量
  → SAC + Structured Graph-SLT
```

因为 `use_topology=False`：

- 不从 SUMO 路网构建 lane topology graph；
- vehicle-to-topology query 返回零 context；
- 车辆边特征中的 `same-lane` 和 `conflict` 两维为零；
- 最终 route/goal attention 只读取 ego 的候选路线 tokens，不拼接全局 topology tokens。

因此，TemporalGraph 主要依赖观测到的相对位置、相对速度、航向差、TTC 和候选路线来学习交通交互。它保留细粒度的时空车辆关系，同时避免全局拓扑 token 带来的额外容量、噪声和优化负担。

### 2.3 Full+BalancedSlots

Full+BalancedSlots 的配置为：

```text
use_topology = True
normalize_slots = True
```

它在 TemporalGraph 的时空车辆图基础上，同时加入两项机制：**静态车道拓扑查询**和**三槽非仿射归一化**。

#### 2.3.1 静态车道拓扑编码

模型从 SUMO `map.net.xml` 构建最多 64 个 lane nodes、最多 256 条 typed edges 的确定性拓扑图。每个 lane node 包含 10 个重采样几何点和 8 维车道属性；五类关系为：

1. successor；
2. predecessor；
3. left；
4. right；
5. conflict。

lane geometry 先经过 point encoder 和 max pooling，再与 lane attributes 融合，随后通过两个 relation-specific residual topology layers，形成每个车道的 128 维 topology token。

#### 2.3.2 车辆—拓扑软查询

每个 actor 的每个历史帧以路线增强后的 vehicle token 查询所有有效 topology tokens。注意力分数除内容相似性外，还加入车辆到 lane polyline 的高斯距离偏置：

\[
b_{im}=-\frac{d(p_i,\ell_m)^2}{2\sigma_t^2}.
\]

查询得到的 topology context 与 vehicle intent token 残差相加，再送入车辆图。这使模型能够把车辆状态与局部车道结构、上下游关系、邻接车道和潜在冲突关系对齐。

#### 2.3.3 拓扑关系进入车辆边

车辆对同一 lane token 的注意力重叠被用作 soft `same-lane` 特征；两个车辆的 topology attention 通过 conflict adjacency 做双线性组合，得到 soft `conflict` 特征。两者加入原有的相对运动/TTC 边特征，再经过两个车辆图层。

#### 2.3.4 Route/goal 融合

TemporalGraph 的最终 goal attention 只使用 ego candidate-route tokens。Full 将这些 tokens 与全部有效 topology tokens 拼接，由 ego token 共同查询。其意图是让 `z_route` 同时表达任务路线和全局可通行结构，而不只依赖短视候选轨迹。

#### 2.3.5 BalancedSlots

产生 32/64/32 三个槽之后，Full 分别应用无仿射参数的 LayerNorm：

\[
\tilde z_k=\operatorname{LN}_{\gamma=1,\beta=0}(z_k).
\]

即每个样本、每个槽内部被中心化并缩放到单位方差，而且没有可学习的 `γ/β` 恢复原幅值。设计目的在于避免某一槽仅凭数值尺度主导 SAC 和 Graph-SLT，使 ego/social/route 三类表征在优化时具有相近量级。

该操作平衡的是**槽位数值尺度**，并不保证各槽的信息量、梯度贡献或策略使用率相同；同时它会消除槽整体幅值中可能承载的置信度信息。这也是 Full 需要通过独立消融验证、不能仅凭名称假定一定更稳健的原因。

### 2.4 两种方法的增量关系与归因边界

| 项目 | TemporalGraph | Full+BalancedSlots |
|---|---|---|
| 逐帧车辆交互图 | 有 | 有 |
| 交互后 temporal attention | 有 | 有 |
| 32/64/32 Structured Graph-SLT | 有 | 有 |
| 静态 lane topology encoder | 无 | 有 |
| 车辆—拓扑软查询 | 无 | 有 |
| same-lane/conflict 拓扑边特征 | 固定为 0 | 由 topology attention 推导 |
| goal attention 输入 | ego candidate routes | candidate routes + topology tokens |
| 三槽非仿射 LayerNorm | 无 | 有 |
| 平均参数量 | 1.438 M | 2.017 M |
| Train ms/update | 257.84 | 379.73 |
| Inference ms/action | 13.97 | 26.11 |
| Peak GPU memory | 196.95 MB | 299.16 MB |

从 TemporalGraph 到 Full+BalancedSlots **同时**改变 topology query 和 slot normalization，参数量增加约 40%，learner-update 时间增加约 47%，推理时间增加约 87%，峰值 GPU 内存增加约 52%。因此当前冻结矩阵只能估计这两个改动的联合增量效果，不能把性能变化单独归因给拓扑查询或 BalancedSlots。若要识别单组件因果贡献，需要另外预注册 `topology on/off × slot normalization on/off` 的正交 2×2 消融；不应从当前联合对比事后拆分。

实现依据见 [`algos/sb3_torch/topo_temporal_features.py`](../algos/sb3_torch/topo_temporal_features.py)、[`algos/sb3_torch/graph_representation.py`](../algos/sb3_torch/graph_representation.py)、[`envs/sumo/topology_graph.py`](../envs/sumo/topology_graph.py) 和 [`configs/sb3_configs.py`](../configs/sb3_configs.py)。

## 3. “确定性 evaluation”的准确含义

这里的“确定性”不是让 50 个回合完全相同，也不是声称环境不存在随机性，而是：

> 策略动作不进行随机采样，并使用固定、可复现的环境 seed 序列和交通文件顺序完成测试。

### 3.1 策略动作确定性

每次需要策略决策时，评估器调用：

```python
model.predict(observation, deterministic=True)
```

实现见 [`algos/sb3_torch/evaluation.py`](../algos/sb3_torch/evaluation.py)。具体含义为：

- SAC、MST、MST+SLT、TemporalGraph、Full+BalancedSlots 使用连续动作策略的确定性均值动作，不从动作分布随机采样；
- PPO 使用 `tanh(mean)`，而不是从高斯分布采样，见 [`algos/sb3_torch/ppo.py`](../algos/sb3_torch/ppo.py)；
- `model.predict()` 将策略切换至 evaluation mode，因此 dropout 关闭；
- `source_evaluation_augmentation()` 额外关闭训练时的随机旋转增强。

因此，同一模型面对相同观测时，不会因为测试阶段的策略采样而输出不同动作。

### 3.2 每回合 seed 序列固定

对训练 seed \(s\)，evaluation 的起始 seed 为：

\[
10000+s
\]

第 \(e\) 个测试回合使用：

\[
\text{episode seed}=10000+s+e,\quad e=0,\ldots,49
\]

因此：

| 训练 seed | 50 个 evaluation seeds |
|---:|---|
| 0 | 10000–10049 |
| 1 | 10001–10050 |
| 2 | 10002–10051 |

编排器生成起始 seed 的代码见 [`tools/reproduce_paper_sb3_sumo.py`](../tools/reproduce_paper_sb3_sumo.py)，逐回合递增逻辑见 [`algos/sb3_torch/evaluation.py`](../algos/sb3_torch/evaluation.py)。

每次 `reset()` 时，该 episode seed 同时传给 Gymnasium 环境和 SUMO 的 `--seed` 参数，见 [`envs/sumo/paper_env.py`](../envs/sumo/paper_env.py)。环境会覆盖多个固定的伪随机实现，但其调用顺序是可复现的。

三个训练 seed 的 evaluation seeds 高度重叠：联合起来只有 10000–10051 共 52 个不同 seed，而不是 150 个互不相同的环境 seed。该安排有利于方法间配对比较，但不能把 150 次 rollout 简单视为 150 个相互独立的交通条件。

### 3.3 六种方法严格配对

对于固定的“场景 + 训练 seed”，六种方法共同使用：

- 相同的 50 个 evaluation seeds；
- 相同的 evaluation 交通文件顺序；
- 相同的回合上限；
- 相同的确定性动作规则。

矩阵共有 6 场景 × 3 训练 seeds = 18 个配对组，每组包含 6 种方法。对最终产物的只读核验未发现 seed 序列或交通 XML 顺序不一致。

### 3.4 Evaluation 交通文件如何固定

五个 SMARTS 来源场景按照以下规则划分交通文件：

1. 将 `traffic_*.rou.xml` 按文件名字典序排序；
2. 将满足 `index % 5 == 0` 的文件固定划入 evaluation partition；
3. 其余文件只用于训练；
4. 50 个测试回合从固定的 seed-42 初始滚动位置开始，按固定顺序循环 evaluation XML。

实现见 [`envs/sumo/paper_env.py`](../envs/sumo/paper_env.py) 和 [`envs/sumo/paper_scenario_registry.py`](../envs/sumo/paper_scenario_registry.py)。实际文件划分为：

| 场景 | 全部 XML | 训练 | Evaluation | 训练/测试资产互斥 |
|---|---:|---:|---:|---|
| Left Turn | 59 | 47 | 12 | 是 |
| Double Merging | 118 | 94 | 24 | 是 |
| Roundabout-A | 30 | 24 | 6 | 是 |
| Roundabout-B | 40 | 32 | 8 | 是 |
| Roundabout-C | 15 | 12 | 3 | 是 |
| CARLA | 1 | 1 | 1 | 否 |

因此，五个 SMARTS 来源场景的训练/测试交通 XML 是互斥的，但 50 个回合会循环使用有限数量的 evaluation XML。

CARLA SUMO 重建场景只有一个交通 XML，训练和测试都会使用该文件。它仍具有固定的 SUMO seed 序列，但不能被描述为 held-out traffic-asset 泛化。

### 3.5 动作保持与 raw-step 时钟

回合上限按 0.1 秒的原始 SUMO 步计数，而不是按策略决策次数计数：

- SAC、MST、MST+SLT、TemporalGraph、Full+BalancedSlots：一次策略动作由环境最多执行 3 个 raw SUMO steps，即约 0.3 秒；
- SMARTS PPO：每个 0.1 秒 raw step 重新决策；
- CARLA PPO：环境每次推进一个 raw step，但同一策略动作保持 3 次。

如果成功、碰撞、越界或达到时间上限发生在动作保持期间，执行循环立即停止，不会强行补齐三步。实现见 [`envs/sumo/sumo_env.py`](../envs/sumo/sumo_env.py)。

逐回合产物中的字段含义为：

- `decision_steps`：实际策略决策次数；
- `environment_steps`：环境包装器的 `step()` 调用次数；
- `raw_steps`：真实执行的 0.1 秒 SUMO 原始步数。

- `profile="paper"`：决定训练预算为 100,000 raw steps，并规定每模型评估 50 回合；

## 7. 统计与报告口径

每个训练模型评估 50 回合。每个“方法 × 场景”单元包含 3 个训练 seeds，因此共有：

\[
3\times 50=150
\]

次 policy rollout。完整矩阵共有：

\[
108\times 50=5400
\]

次 evaluation rollout。

但由于三个训练 seed 的 evaluation seed 序列重叠、交通 XML 也会循环使用，不能把同一单元的 150 次 rollout 当作 150 个独立实验单位。主要不确定性仍应来自三个独立训练 seed，方法比较则利用相同环境序列进行配对。冻结协议使用训练 seed 层级统计和配对层级 bootstrap，避免将重复环境 rollout 当成完全独立样本。

此外，正式矩阵的周期 evaluation 频率为 0；训练结束后才执行最终 50 回合测试。主结果使用 100,000 raw-step 的最终周期 checkpoint，不依据 held-out evaluation 表现选择 checkpoint，从而避免测试集选择泄漏。

## 8. 推荐的论文表述

可在论文实验设置中写为：

> Each trained policy is evaluated for 50 episodes using deterministic mean actions. For training seed \(s\), evaluation episodes use the fixed SUMO seed sequence \(10000+s,\ldots,10049+s\). All methods with the same scenario and training seed share the same ordered held-out traffic partition, seed sequence, and episode limit. Episode horizons follow the released source-code protocol—400/600/400/600/1000/302 raw 0.1-s simulation steps for Left Turn, Double Merging, Roundabout-A, Roundabout-B, Roundabout-C, and CARLA, respectively—rather than the conflicting 400/800 limits reported for Double Merging/Roundabout-C in Table VI.

对应中文表述为：

> 每个训练模型在冻结的 evaluation traffic partition 上执行 50 个确定性策略回合；策略使用均值动作而不进行随机采样。对于训练 seed \(s\)，测试回合使用固定的 SUMO seed 序列 \(10000+s\) 至 \(10049+s\)。同一场景和训练 seed 下的所有方法共享完全相同的交通文件顺序、测试 seed 与回合上限。回合上限采用作者发布源码口径，六场景依次为 400/600/400/600/1000/302 个 0.1 秒 raw simulation steps，而不是论文 Table VI 在 Double Merging 和 Roundabout-C 中给出的 400/800 步。

## 9. 解释边界

当前 Double Merging 和 Roundabout-C 分别比论文描述多 200 raw steps，即多 20 秒测试时间。这可能：

- 降低 timeout rate；
- 提高 success rate；
- 改变成功样本构成及其 completion time；
- 影响与原论文数值的直接比较。

因此，当前结果可以用于当前六方法系统性矩阵内部的公平配对比较，但与论文 Table II/III 数值直接对照时，必须明确披露 Double Merging 和 Roundabout-C 采用的是发布源码上限，而非论文表格上限。
