# v4.9.2：严格纯学习部署协议

## 决策结论

v4.9 的四个开发作业均通过门禁，且最终部署都由 `target_critic`
产生。运动学安全投影复审进一步确认，运行中的最终策略没有外部运动学
投影、TTC/车头时距阈值、车道变更否决、几何伪标签或解码后动作改写。
不过，旧选择器仍把带固定 `0.90` 置信条件的 `fusion_0_90` 放在候选集
中；这不符合“不得添加规则机制”的最新科学约束。

v4.9.2 因此只做一个合规性协议变更：把候选解码器固定为纯学习的
`target_critic`，仍在 `highest_training_success` 和 `exact_final` 两个检查点
间使用训练划分上的成对校准；只有两个检查点在主校准结果完全并列时，
才运行预注册的第二个训练校准种子块。若二次校准后仍并列，固定选择
`exact_final`。校准和选择都不读取 validation 或 test。

## 为什么当前不立即改网络

完整 M1--M4 轨迹归因显示，碰撞前窗口中学习碰撞价值通常已经上升；在
实际碰撞轨迹里，被执行动作也常是模型预测的最低碰撞价值动作，或与其
差距很小。RAM 场景的排序辨识较弱，但四个开发单元已经通过。此时根据
这些 validation 数值继续调网络，会把开发场景重复用于方法选择。

因此，v4.9.2 不声称改进模型本体，也不把合规性变更伪装成性能创新。
它先用未见过的 promotion 种子检验现有学习模型。只有 promotion 相对
TemporalGraph 未过门禁时，才进入 v4.10 的新开发阶段，检验“共享稳定
表征上的碰撞头和可训练碰撞表征梯度”这一模型假设。

## 开发证据采用门禁

现有 v4.9 开发结果只有在以下事实全部由只读、哈希绑定的重算证明时才可
作为 v4.9.2 开发通过证据：

1. 四个运行原本选择的解码器都是 `target_critic`；
2. 只保留 `target_critic` 后，从原始 train 校准文件重算出的检查点与原
   选择相同；
3. 源检查点 SHA-256 和最终策略参数状态 SHA-256 均相同；
4. 重算过程不改写任何已完成运行文件，也不读取 validation/test 进行
   重选择。

任一条件不满足，就必须重新运行完整 v4.9.2 开发矩阵，不能直接进入
promotion。

## Promotion 与失败后路线

当前 promotion 固定为 2 个方法 × 3 个场景 × 2 个种子，共 12 个新训练
作业。任一作业失败都不会取消剩余作业；全部尝试结束后统一保存接受状态、
汇总和门禁结论。promotion 通过前，120 个 test 作业保持锁定。

若 promotion 失败，将先按场景、种子、碰撞前窗口、风险排序能力和动作
提议差距做深层归因，再新增 v4.10 文件。v4.10 只能完善学习表征或损失，
不得加入运动学投影、阈值门、置信门、人工几何标签、否决器或动作改写。
