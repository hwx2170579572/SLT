# p=0.2 / p=0.3：SAC+MLP 100k 结果与问题定位

日期：2026-09-30。两路均为 train seed=0、从零 100,000 raw 控制步、95,001 次更新，使用 final_model 在 100 个共同 validation 逻辑种子 10000–10099 上确定性评估；实际 SUMO seeds 为 1000010000–1000010099。完成文件、checkpoint SHA 与评估身份已核对。以下只分析已有正式日志，另做了一个无环境、无训练的 CPU replay-buffer 人工数据探针。

## 1. 结论与证据强度

最直接的问题是 p02 最终策略的横向控制：它频繁向较小车道索引换道，最终大量停在无法接续既定左转路线的进口车道。p03 则反复发出向左命令，在左侧边界通常不产生换道，保留能转弯的车道，但以较高速度进入路口并频繁碰撞。p03 成功率较高不能解释为较大 p 使环境更容易，也不能概括成安全性更好。

两档的实际在网车量和实际入场率非常接近，额外请求主要积压在网外。奖励对错车道停滞缺乏及时反馈、随机训练与确定性评估的差别、共享的非标准 n-step bootstrap 口径，都是需区分的进一步因素。现有证据不能把最终差异唯一归因于学习率、奖励系数或一个训练 seed 的随机性。

## 3. 横向控制与路线可达性是最直接的机制

自车初始车道为 -E1_2，路线为 -E1→-E0。路网中唯一接续该路线的连接是 -E1 lane 2→-E0 lane 1；进口 lane 0/1 不具备这条目标连接。三个进口车道长度均为 70 米。

p02 的 70 个 timeout 中，56 个终局在 -E1_0、13 个在 -E1_1，均未进入下一条路线 edge；另 1 个在左转 internal lane。即 69/70 个 timeout 集中在不兼容目标转向的进口车道。timeout 组平均实际速度 1.17 m/s、停驶 tick 比例 76.1%，但请求的平均目标速度约 5.15 m/s；终局中位目标速度约 4.96 m/s。不能把低实际速度直接解释成策略主动请求停车。

动作 a0 映射为 clip((a0+1)*5, 0, 10) m/s。a1<-1/3 请求 lane -1，a1>1/3 请求 lane +1，否则保持车道；在当前 SMARTS 契约中 +1 增加 SUMO 车道索引（向左），-1 降低索引。p02 timeout 最后 10 个决策共 700 个动作中，有 579 个 lane -1。SUMO 自主变道 mode=0、自动 teleport 关闭；离开合法左转车道后需要策略自己回到正确车道。结合终态位置，这强支持“错误选道后未能回到可达车道，在入口末端超时”的机制。

p03 碰撞组所有 2,741 个决策都请求 lane +1，记录的 lane_change_applied 均为 false；该策略在初始 lane 2 的左侧边界通常保持合法车道。碰撞组平均实际速度约 8.46 m/s，全部 83 次碰撞终态位于路口 internal lane，终态速度均值约 9.27 m/s。它能更频繁进入路口，但并未学成可靠的安全让行策略。lane_change_applied=true 只代表 TraCI 命令提交未抛异常，不等于实际变道已完成。

补充判据核验：ego 使用 speedMode=0 与 laneChangeMode=0，策略承担安全速度、让行和选道控制。终局 collision 只由涉及 ego 的 SUMO 碰撞事件或 ego 几何重叠触发；纯背景车之间的碰撞不会单独结束回合。全局碰撞参与者可能出现在诊断列表中，不能与 ego 终局判据混同（sumo_env.py:1128-1191,1227+）。

## 4. 这两档主要改变网外积压，不能作为清晰的实际密度梯度

以下为自车接管前 t=50 秒、100 回合均值；所有该时点均无 ego，30/40/50 秒计数平衡检查全部通过。

| 指标 | p02 | p03 |
|---|---:|---:|
| 到时请求 | 300.28 | 449.20 |
| 累计实际入场 | 80.36 | 80.71 |
| 在网背景车 | 29.39 | 29.25 |
| 停驶背景车（速度<0.1m/s） | 0 | 0 |
| 路网外待入场 pending | 219.92 | 368.49 |
| 平均入场延迟（秒） | 16.76 | 18.88 |

100 对种子中 p03 请求和 pending 都更多，但在网车辆差有正有负；50 秒在网差均值为 -0.14 辆，实际入场差均值为 +0.35 辆。控制期按时长归一的实际入场约 5,400 辆/小时，明显低于两档 21,600 / 32,400 辆/小时的请求量。p02 超时多数持续 60 秒，p03 碰撞平均约 9.8 秒，因此累计控制期入场量不能直接横比。

到达请求的共同随机数及嵌套性成立；逐车 vType 参数完全匹配尚未验证。相同在网数量也不保证相同局部冲突间隙。只能确认两档均处于明显受插入限制的高请求状态，不能用 p03>p02 推导实际任务难度必定更高。

## 5. 奖励与训练目标需要分开审视

实际学习奖励由 GeneralizedRewardShapingWrapper 重建，覆盖底层 reward：

`r_decision = terminal_bonus - 0.01 + 0.02 * delta_route_distance_m`

terminal_bonus 按优先级为 success +10、collision -10、off_route -10、timeout -5，平时为 0。步代价按 decision 而非 raw tick 收取；一次 decision 最多 3 个 raw tick。底层 SUMO 的事件奖励没有再叠加进训练奖励。

当前没有针对“不兼容路线的车道/反复无效换道”的即时专项惩罚；相关失败可能直到 60 秒 timeout 才反馈。以完整回合未折扣塑形回报看，p02 timeout 均值 -5.598046，collision 均值 -9.573909，success 均值 +11.827352。因此躲避碰撞但无法完成的行为可能比一次失败的冒险穿越少受罚；这与安全性优先的设定并不自动矛盾，但可能偏离希望安全且及时完成的训练目标。仅提高等待或 timeout 惩罚可能把超时推向碰撞，需区分“安全成功增加”和“失败类别变换”。

两路评估塑形回报总和均值分别为 p02 -5.720742、p03 -5.049319；evaluation_results.mean_return 则为 p02 -0.20、p03 -0.66，后者来自成功 +1、碰撞 -1、timeout 0 的原始结果分数。这两个量不能混用，也都不等同于 SAC 的折扣加熵优化目标。

600 raw 上限目前作为 truncated 处理，timeout 会继续 bootstrap。若 60 秒仅是外部采样截断，这有合理依据；若 60 秒内完成是任务本身要求，则需要明确有限时域、终止语义和时间观测契约。本次没有审计剩余时间是否进入 observation，不作断言。

## 6. 已执行确认的非标准 n-step 折扣与超参数边界

两个 final_model 保存的参数相同：lr=1e-4，batch=32，replay=20,000 decision transitions，n_steps=4，gamma=.99，raw_learning_starts=5,000，train_freq=1 decision，gradient_steps=3，ent_coef=auto_0.2，target_entropy=-2，tau=.005。各实际完成 95,001 updates；不存在一组未真正训练或预算更短的证据。

本地 replay buffer 累加 `r0 + gamma*r1 + gamma^2*r2 + gamma^3*r3`，但窗口末 bootstrap 仍乘 gamma，而非标准 4 步的 gamma^4。源码明确注释这是保留 released SAC 实现，不能误称本次新增场景引入的改动。

无环境、无模型训练的 CPU 人工探针已确认：奖励 [1,2,3,4] 得到 9.8014965，next_obs 到第 4 步，discount=.99；标准 gamma^4=.96059601。非终止、timeout 和真终止三例均如此，timeout 的 dones=0 保留 bootstrap，真终止 dones=1。该问题是确定的实现口径差异，尚未通过对照训练确定对最终性能的影响方向。它是两路共有因素，不能单独解释为何 p02 更差；继续调参前应先决定研究要复现 released 目标还是对齐标准 n-step。

训练末 100 个完整回合，p02 为 16 成功/84 碰撞/0 超时，p03 为 14 成功/86 碰撞/0 超时；确定性验证却出现 p02 70% 超时。训练使用随机动作采样，验证使用确定性输出，横向动作还通过阈值变成离散命令。这提示随机探索对回到正确车道的帮助及确定性策略的脆弱性；训练窗口中的模型也在变化、种子 split 不同，仍需固定模型的对照评估才能分离因素。

p02 全训练共有 487 个完整回合、74 次成功；p03 有 605 个完整回合、99 次成功。同 raw 预算并不保证同数量的独立尝试或成功样本。末尾 alpha 约 .0088/.0093，优化日志指标有限且不是严格同步，不能用一次 critic loss 或 TD 误差直接断言学习率错误或已收敛。保持超参数一致是本次控制变量的正确做法；适配性需要独立验证。

## 7. 优先级明确的后续建议（本次未执行）

1. 先做无需重新训练的选道诊断：固定 p02 最终模型、原评估 seeds 和纵向输出，只在诊断分支保持当前合法车道（横向命令 0），比较 timeout、collision、success 及停滞位置。该结果用于检验机制，不替换原正式评估。是否将路线车道约束纳入正式任务，取决于研究是否需要策略负责选道，不能直接删掉这一任务后声称原方法改善。
2. 明确 n-step 与 timeout 契约。若修改 bootstrap、终止或奖励，保留旧实现结果，并为所有对比方法使用统一新协议；不要同时改学习率、奖励和场景后做单因素归因。
3. 再标定实际中等车流。当前 p=.2/.3（以及之前 p=.5）均有明显入场积压，且 SAC+MLP 100k 成功率低于既定 30%–60% 目标。此前建议的每 tick p=.03 等更低请求量仍是未验证候选，应依据正常预热的实际入场/占用及固定训练预算校准。不要继续以增加模块来掩盖场景或训练契约问题。
