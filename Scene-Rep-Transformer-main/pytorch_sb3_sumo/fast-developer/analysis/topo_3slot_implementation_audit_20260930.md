### ST-RT → Topo: what is added

ST-RT and Topo retain the same route injection and vehicle/temporal backbone. The executed change is `use_topology=false→true` (run manifests/arguments); in the code this is a bundle of topology effects, not an isolated learned “GT token”:

1. Encode the static lane graph and query it per actor/history frame (`incremental_topo_encoder.py:309-333`, `topo_temporal_features_v2.py:453-531`).
2. Add `topology_residual_scale × topology_context` to route-injected state tokens before the vehicle/temporal trunk (`incremental_topo_encoder.py:334-335`).
3. Replace geometry/motion-only edge features with an 8-channel relation-aware edge feature: Δposition(2), Δvelocity(2), cos(heading difference), normalized closing TTC, same-lane attention overlap, and conflict-or-merge attention overlap (`topo_temporal_features_v2.py:537-594`). The last two are induced by lane attention; conflict and merge are combined as `max(A_conflict,A_merge)` for this policy channel even though the graph encoder has six relation types (`topology_graph_v2.py:42-44,347-367`).
4. Add a goal-side topology residual to route readout (`incremental_topo_encoder.py:394-409`).

Main topology fusion is `LN(intent + α_topo·context)`; the `use_topology=false` branch still applies the same `topology_norm` to `intent` (`incremental_topo_encoder.py:334-352`). The goal readout is `r + LN(r + α_goal·t) − LN(r)` (`:400-409`), which is exactly `r` at `α_goal=0`; an added LayerNorm by itself is not a supported explanation for the Topo regression. The base `topology_residual_scale` is also used to scale the two vehicle relation channels (`topo_temporal_features_v2.py:584-594`), coupling token-context and edge-cue magnitudes. The goal gate is separate.

Route-aware sparse query details (`topo_temporal_features_v2.py:362-425,453-531`): route distance is polyline-to-lane-point geometric `cdist`; route direction and vehicle/lane heading cosine enter a soft bias; `compatible = valid_global_lane_nodes AND heading_cosine >= reverse_heading_cosine_min` (default 0), then biased top-8 selection, with a nearest-valid-node fallback if no compatible node exists. This is not a route-successor legality or right-of-way mask. Although the static graph contains successor/predecessor relations, the current ego query mask does not test whether a candidate lane connects to the ego route's next edge. The goal branch's `ego_topology_valid` is the last valid-frame ego `topology_key_mask` (`incremental_topo_encoder.py:398-403`), not a second route-connectivity mask.

The topology graph carries node IDs in graph-building metadata (`topology_graph_v2.py:105-124`), but the encoder's tensor inputs/buffers are lane points, lane attributes, masks and indexed relation arrays (`topo_temporal_features_v2.py:248-278`); the policy observation itself supplies geometry-only `map` polylines. Therefore a route-connectivity constraint would require an explicit route-edge↔topology-node correspondence (or a validated geometry-based mapping) plus a new mask/feature path. It is not recoverable merely by changing the current cosine threshold. The model may still learn connectivity implicitly through relational graph embeddings; no evidence here shows that it did or did not.

For the observed Topo timeouts, this limitation is directly relevant but is not proof that attention caused the action. The checked SUMO route file configures ego route `-E1 -E0`, `departLane=2`, `arrivalLane=1` (`ego.rou.xml:3-4`). `paper_env.py:218` passes the scenario's `ego_route_path` as a SUMO route file; the only dynamic `route.add`/`vehicle.add` path is endless background re-insertion and excludes ego (`paper_env.py:508-538`). No runner or environment ego route/depart-lane override was found. This verifies the static ego configuration is applied to SUMO, but the initial lane is not separately claimed as per-episode trajectory-observed here. The checked network has 70 m lanes on `-E1` (`map.net.xml:99-102`) and its only `-E1→-E0` connection is `fromLane=2→toLane=1` (`map.net.xml:169`); lanes 0 and 1 have no such connection. `intersection_sorted` inherits `source_observation_contract="smarts"` (`paper_scenario_registry.py:25,100-104`). Action mapping is `action[1] < -1/3 → command -1`, `>1/3 → +1`, otherwise 0 (`sumo_env.py:1014-1025`); under this contract the SUMO lane offset equals the command (`:1132-1136`), and increasing lane index is left (`:1027-1028`). Thus repeated -1 commands move from the route-compatible lane 2 toward lower-index/right lanes 1 then 0. In lane 0 another -1 request is out of bounds and `_apply_control` returns false before TraCI (`:1027-1055`).

Run episode diagnostics/reporting supplied the behavioral half of the evidence: all 22 Topo timeout terminals were road `-E1`, lane `-E1_0`, route index 0, position 70 m; terminal speed was 0 despite mean requested target speed 5.020 m/s (range 4.250–6.491); 16 final lane commands were -1 and 6 were 0; `lane_change_applied=false` on all final decisions; observed stop fraction was about 84% and average actual speed 1.167 m/s. The lane mismatch is a strong near-cause for those timeouts. `lane_change_applied` reports local validity/request-call success for that decision, not physical completion; its terminal false value does not show whether earlier lane-change requests succeeded. Why the learned policy moved right is still unproven. In particular, the current evidence does not establish that Topo attention directly caused it.

The run arguments record terminal reward weights `success=+10`, `collision=-10`, `off_route=-10`, `timeout=-5`, `progress_scale=.02`, and `step_cost=.01`. The current `GeneralizedRewardShapingWrapper` computes `r = terminal_bonus - 0.01 + 0.02·Δdistance_m`, where only the first matching terminal event is used (`reward_shaping_v2.py:79-118`); the wrapper source itself is not separately hash-listed in this run's source snapshot, so the weights are run facts and the formula is current-source evidence. Action mapping in the source is `speed=clip((action[0]+1)·5,0,10) m/s`, and lane command is -1/0/+1 at action[1] thresholds ±1/3 (`sumo_env.py:1014-1025`). For this scenario the inherited SMARTS contract maps lane command directly to SUMO lane-index offset (`:1132-1136`). Thus the reported nonzero speed targets and repeated negative lane commands refer to different action dimensions.

## Topo → 3slot: readout and gradient differences

The common `ego_component`, `social_component`, and `route_component` are each 128-D. Social attention uses the ego as query and all valid actor features, including ego, as keys (`incremental_topo_encoder.py:386-391`). Ego is already route-injected, topologically fused and processed by the graph/temporal trunk; route component receives the goal topology residual. These are overlapping upstream views, not disjoint or guaranteed disentangled semantic sources. The SAC actor and critic then mix the returned 128-D feature nonlinearly through `net_arch=[128,32]`.

Topo output: `MLP(384→128→128)` with ReLU after both Linear layers (`incremental_topo_encoder.py:168-174`), 65,792 active output-head parameters. Topo+3slot output: three Linear projections 128→32, 128→64, 128→32, concatenated to 128 (`topo_temporal_features.py:432-448`; incremental selection at `incremental_topo_encoder.py:418-425`), 16,512 active parameters. No ReLU, LayerNorm or dropout is applied after the incremental projections; parent `normalize_slots=False` (`topo_temporal_features_v2.py:225-233`; normalization is conditional in `topo_temporal_features.py:682-688`). The 3slot readout therefore changes fixed linear compression, active capacity (about 74.9% fewer parameters) and pre-SAC cross-component mixing. It does not turn on SLT/SBS. Both heads are instantiated unconditionally in the same extractor construction order (slot projections in the base constructor, joint head in the incremental subclass constructor); `use_slots` selects only which already-registered head participates in forward. Registry totals and parameter-name/shape order match (135 parameter tensors / 1,057,988 elements per encoder); active counts differ. Because the workers used the same training seed and construction path, there is no code-level reason to expect common parameters to have different initializations, but no initial-weight snapshot was saved for a bitwise initialization comparison. Counts come from offline model parameter/gradient inventory, not FLOPs.

Both runs use `SceneRepresentationSAC`, `representation_coef=0`, no Graph-SLT/SBS and no auxiliary representation optimizer/loss. `DetachedSceneActor` detaches shared-extractor features and its optimizer excludes the extractor; online critic owns/includes the shared extractor (`policies.py:18-29,88-125`). The target critic has an independent extractor and Bellman-target evaluation is under `no_grad` (`sac.py:330-367`). The online encoder, Topo branches, and active readout are consequently updated by critic TD loss only; actor gradients update actor head parameters, not encoder parameters. Critic TD gradients are captured after `critic_loss.backward()` and before clipping (`sac.py:361-420`). In the saved gradient samples, Topo-core/fusion/vehicle-relation groups and each active slot projection had gradient coverage; this excludes a wholly disconnected branch at sampled updates, not useless or harmful representation learning.

## Evidence-bounded next tests

1. **Topo-focused route-feasibility test.** Preserve ST-RT+Topo trunk and joint readout, and make the ego goal-topology pathway receive explicit lane-to-next-route-edge reachability, using only the fixed map and planned route. Keep the actor's true physical lane and social/conflict cues; do not delete non-route lanes from actor topology queries. Because next-edge identity is not directly present in the current observation/buffer interface, first implement and unit-test the route-edge↔lane-node mapping (or a clearly validated polyline matching) and log reachable-lane mask/attention separately. Then compare from zero under the same route/traffic seeds. Success should include fewer illegal-lane-end timeouts without an offsetting collision increase; merely exchanging timeout for collision is not success. This targets a direct near-cause, but does not assume topology attention caused the rightward commands.
2. **3slot readout-capacity control.** Keep the Topo trunk and 32/64/32 output partition, but give each branch the sequence `Linear(128,128) → ReLU → Linear(128,d) → ReLU`. Total active head size is 66,048 vs the joint baseline's 65,792 (+0.39%); the final ReLU also matches the baseline's nonnegative output contract. This tests a structured nonlinear readout at nearly matched capacity without adding an auxiliary objective. It still does not isolate all slot semantics; if it recovers, capacity and nonlinear factorization remain bundled. Do not claim 3slot is invalid from the current single seed.

These are proposals only. No new model was implemented or trained during this audit.
