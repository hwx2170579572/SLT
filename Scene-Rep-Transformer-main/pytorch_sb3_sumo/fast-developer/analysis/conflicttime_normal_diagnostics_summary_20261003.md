# Conflict timing: path-deviation audit

The existing B-evaluation calibration file contains 15,881 rows, including 10,297 `candidate_path_deviation` outcomes. Its first three deviation rows are summarized with their source identifiers and selected paths in [the audit JSON](D:/Program%20Files%20(x86)/paper/Scene-Rep-Transformer-main1/Scene-Rep-Transformer-main/pytorch_sb3_sumo/fast-developer/analysis/conflicttime_path_deviation_evidence_20261003.json). They are not three independent events: the first two are consecutive forecasts for the same seed-10000 episode/foe encounter. Those rows show which selected path was left and that the initial candidate enumerations were not marked truncated, but they do not retain the mismatch-time lane/position or selected path termination reason. They cannot distinguish a legal alternate lane change from incomplete static candidate coverage. The third row has the same limitation for ego; its foe entry interval remains left-censored rather than being replaced by the deviation.

Before this change, calibration marked an actor `route_or_candidate_path_deviation` when its projected lateral distance from the selected polyline was **greater than 5 m**, or when a known current lane was absent from that selected path’s lane list. This is a path-consistency observation, not proof that an actor made an illegal maneuver or could not recover. The check runs at the next policy-decision observation, so the exact raw tick within the action-repeat interval is unknown. The calibrated status alone cannot identify candidate-chain cutoff, legal lane changes, or missed internal-lane alternatives.

The passive addition to [the observation wrapper](D:/Program%20Files%20(x86)/paper/Scene-Rep-Transformer-main1/Scene-Rep-Transformer-main/pytorch_sb3_sumo/envs/sumo/conflict_timing_observation.py#L749) stores `path_deviation_evidence` in an already emitted calibration row. For the first deviating sample on each actor side, it records raw step and decision index, observed road/lane/position, projected path position and lateral distance, lane membership, trigger reason, selected path lane IDs, and whatever candidate termination/truncation metadata was already available. Missing termination metadata is explicit as `unknown`. It uses the existing observation snapshot and candidate metadata; it does not query a background vehicle’s future route, add prediction rows, or alter features, reward, actions, or the deviation rule. Existing entry and clearance intervals remain intact when only one side deviates. Historical run files were not rewritten: all 15,881 stored calibration rows lack the new field.

The pure test module [test_route_conflict_timing_observation.py](D:/Program%20Files%20(x86)/paper/Scene-Rep-Transformer-main1/Scene-Rep-Transformer-main/pytorch_sb3_sumo/tests_sb3_sumo/test_route_conflict_timing_observation.py) passes **7 tests**. They cover the strict 5 m boundary, lane mismatch, first-sample capture, known versus missing path cutoff metadata, and preservation of an existing one-sided interval. No SUMO process or simulation was invoked.
